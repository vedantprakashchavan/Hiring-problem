How it works

The greedy strategy

One candidate per day. One rule: always keep the best. Simple in theory — but what does it cost?

01
📋
Interview

Agency sends one candidate each day. You always pay the interview fee ci — no matter what. This cost is unavoidable: n × ci total.

02
⚡
Compare & decide

If the new candidate outscores everyone you've seen so far, you fire the current hire and pay the hire fee ch. You're committed to always having the best.

03
💰
Count the cost

Total cost = n·ci + (# hires)·ch. With random ordering, expected hires ≈ H(n) ≈ ln(n). A logarithmic bound — much better than worst case.

Mathematical Analysis

The probabilistic argument

Why does random order make this problem tractable? Indicator random variables give us the clean answer.

Indicator random variables

Let Xᵢ = 1 if candidate i is hired.
Candidate i is hired iff they are the best among the first i candidates.

Under a uniformly random permutation:
Pr[Xᵢ = 1] = 1/i

By linearity of expectation:
E[X] = Σᵢ₌₁ⁿ E[Xᵢ] = Σᵢ₌₁ⁿ 1/i = H(n)

Total expected cost

Interview all n candidates (always):
+ n · cᵢ

Expected hiring cost:
+ cₕ · H(n)

Where H(n) = ln n + γ + O(1/n)
and γ ≈ 0.5772 (Euler–Mascheroni constant)

E[cost] = n·cᵢ + cₕ·ln n
Best case
O(n·cᵢ + cₕ)
Only one hire: the very first candidate is the global best. You pay n interviews and one hire fee. Happens when the first candidate turns out to be rank #1.
Worst case
O(n·cₕ)
Candidates arrive in strictly ascending order of quality — you hire every single person. Cost = n·cᵢ + n·cₕ. The nightmare scenario for HR.
Expected case
O(n·cᵢ + cₕ·ln n)
Under random input permutation, expected hires is H(n) ≈ ln(n). Even for n = 1,000,000 you only expect ~14 hires.
Randomized algorithm
Always O(cₕ·ln n)
Pre-permute candidates randomly. Now the expected bound holds regardless of adversarial input. This is the power of randomization.
Algorithm

Pseudocode

The complete algorithm, as presented in CLRS Chapter 5. Deceptively simple — the complexity is in the analysis.

HIRE-ASSISTANT(n) // Input: n candidates ranked 1..n (1=worst, n=best) // Candidates arrive in random order (or pre-permuted) best ← 0 // candidate 0 is a least-qualified sentinel for i ← 1 to n // Pay interview cost c_i (always) interview candidate i if candidate i is better than candidate best best ← i // Pay hire cost c_h, fire previous best hire candidate i
